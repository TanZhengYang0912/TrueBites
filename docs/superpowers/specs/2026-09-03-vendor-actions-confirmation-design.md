# Vendors — 图片占位与统一操作确认

## 已确认的目标

用户已确认：点击操作后弹出一次确认框，确认后才执行；所有确认框沿用当前 Delete vendor 的大确认框尺寸和 UI，不使用浏览器原生 confirm 或行内小提示。此文档待用户审阅后进入实施计划。

## 范围与方案

只调整 Vendors 页相关交互，保留现有查询、权限及 API。复用现有 ConfirmDialog 与 admin-confirm-modal 样式，而不是分别创建不同尺寸的审批、保存、删除弹窗。保持当前分支和已有未提交改动，不 push。

- 删除表格 Actions 中的眼睛按钮，保留点击商家行打开详情；商家名称提供可通过键盘触发的详情入口。Action 和选择框不会同时触发详情。
- 无图片或图片加载失败时显示明确的 No photo 占位，尺寸沿用现有缩略图容器。有效图片正常显示，更换图片后可重新加载。不拿同名商家图片或无关素材代替真实照片，也不自动修改数据库图片字段。
- Approve、Suspend：点击后显示商家名称、目标状态及影响，确认才调用状态更新；已有批量入口也使用同样确认方式并显示数量。
- Edit：点击直接打开编辑表单；Save Changes 先执行现有校验与有无改动检查，通过后弹出保存确认。取消确认只返回编辑界面、保留输入，不执行本次 Save 请求。
- Delete：保留并核实单个、批量及重复商家面板已有的确认流程，明确名称或数量、关联资料影响及不可撤销提示。不会因打开或取消弹窗而删除数据。

## 一致的确认框

沿用当前删除框的宽度（桌面最多 420px）、圆角、阴影、标题和正文排版、内边距，以及 Cancel／确认按钮尺寸和排列；窄屏沿用同一响应式规则。标题和说明按操作变化，正文较长时允许自然增高，不裁切信息。Approve／Save 使用常规主色，Suspend／Delete 使用警示或危险色；不改变按钮几何尺寸。

## 交互安全与边界

- 弹窗打开时固定目标商家／所选集合、操作类型及保存内容，防止待确认操作被后台列表刷新或另一选择替换。
- 确认执行期间阻止重复提交，显示进行中状态，关闭入口不应让同一操作绕过防重保护；失败给出明确反馈并保留合理重试路径。
- 支持对话框名称、键盘焦点管理及取消。编辑界面上方的保存确认取消／Escape 只关闭确认层，不误触底层编辑取消和图片回滚。
- 保留现有编辑图片工作流：部分图库上传、自动选封面在编辑时已经提交，关闭编辑会按原逻辑回滚。这次保存确认仅控制 Save Changes 的提交，不声称此前图片动作从未写入；不扩展为图片暂存架构重写。
- 当前尚未取得截图中 suspended Lamille Bakers 的认证记录，因此不能断言具体是缺图还是链接失效；已确认无 URL／加载失败会产生空框的代码路径。

## 验证要求

使用模拟数据测试，不对真实商家执行批准、暂停或删除。

1. 缺图、图片加载失败、正常图片、更换图片后恢复，以及同名不同 ID 的独立显示。
2. 无眼睛按钮，点击行／键盘入口仍可查看详情；其他 Action 不冒泡打开详情。
3. Approve／Suspend／Save：未确认不发送对应写请求；取消不写入；确认仅执行一次。覆盖单个与批量状态操作。
4. Delete 各入口均确认后才删除，取消不发请求；失败及重复点击有保护。
5. 保存无改动／校验失败不弹执行确认；取消保存确认保留表单；嵌套 Escape 不关闭编辑界面。
6. 浏览器直接对比各确认框与 Delete 的宽度、字体、间距及按钮尺寸，检查桌面和手机布局。
7. 运行相关单元测试、浏览器测试、构建及差异检查；实现开始与最终验证按 AGENTS 指示安排有边界的 luna_worker 独立复核。
